# safety · 安全管理

> 本文件按"Jetson ROS 2 层 / STM32 层 / 硬件层"三层重写。
> 上一版把"ROS 2 源码里没有急停程序"写成"机器人没有急停"，**结论越界**，本次修正。

## 1. 分层结论

| 层 | 已确认存在 | 未发现 / 未确认 |
|---|---|---|
| **Jetson ROS 2** | `/cmd_vel` 入口限幅（L185-198）；手柄限速（`joystick_control.py:33-34`）；舵机位置截断（`servo_controller.py:60`）；systemd 自动重启 | 急停节点/话题/服务；指令超时；控制源仲裁；低电处理；通信重连；节点健康检查 |
| **STM32** | Jetson SDK 存在舵机电压/温度/角度/扭矩配置接口；HEX曾检出 `battery_check_timer` 字符串（本轮未独立反汇编） | 是否默认启用这些保护；是否有电机看门狗；是否有指令超时 —— HEX 内无法确认 |
| **硬件** | 未知 | 物理急停按钮、断电保护、电源管理 —— **无资料可判断** |

## 3. 速度限制的真实分布

| 入口 | 限幅 | 代码 |
|---|---|---|
| `/cmd_vel`（Nav2） | ±0.2 m/s、±0.5 rad/s | `odom_publisher_node.py:186-197` |
| `/controller/cmd_vel` | 无 | 直接进运动学 |
| `/app/cmd_vel` | 无（仅条件换算） | `acker_cmd_vel_callback` L200 |
| 手柄 | 0.2 m/s、2.0 rad/s | `joystick_control.py:33-34` |
| 颜色追踪 app | ±0.35 m/s、±2.0 rad/s | `object_tracking.py:104,115` |

同一台机器人，不同程序能给出的最高线速度相差 1.75 倍。

## 4. STM32 层：有哪些保护"接口"

从 Jetson SDK 可见**存在下列保护参数配置/发送接口**；但不能据此证明固件已实现、正确响应、实际执行或默认启用：

| 保护项 | SDK 函数 | 业务层是否调用 |
|---|---|---|
| 舵机角度限位 | `bus_servo_set_angle_limit` | 仅节点透传（`ros_robot_controller_node.py:213`），无业务主动设置 |
| 舵机输入电压限位 | `bus_servo_set_vin_limit` | 同上（L216） |
| 舵机温度上限 | `bus_servo_set_temp_limit` | 同上（L219） |
| 扭矩开关 | `bus_servo_enable_torque` | 同上（L222） |
| 电池阈值 | `set_battery_level(0x2904)` | **无任何调用** |

结论：**SDK接口存在；固件是否接收、支持、执行及默认启用均未知**（HEX 闭源，无法确认上电初始化有没有设置）。
不能据此说"有保护"，也不能说"没有保护"。

## 5. 硬件层

* 交付资料中没有电路图、没有急停按钮说明、没有电源保护文档（`4 硬件资料/` 只有网盘链接与相机/雷达资料）。

## 6. 控制源冲突的实际后果

```
t0  Nav2 经 /cmd_vel 发 0.2 m/s（被限幅）
t1  手柄经 /controller/cmd_vel 发 0.2 m/s（无限幅）
t2  某个 app 追踪经 /controller/cmd_vel 发 0.35 m/s
```

`cmd_vel_callback` 每收到一条就覆盖 `self.linear_x` 并立即 publish，**最后一条胜出**。
上层无法感知"底盘已被占用"。

## 8. 结论（可直接引用）

> **在已检查的 Jetson ROS 2 代码范围内**，尚未发现完整的软件急停、速度指令超时和统一控制源仲裁；不能据此证明全部原厂程序或硬件均无相关功能；
> **Jetson SDK**提供舵机保护参数配置接口，**STM32端**是否响应、实际执行及默认启用均未确认；
> **硬件层**是否存在物理急停与断电保护，现有资料无法判断。
